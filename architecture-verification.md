# Architecture verification — current synthetic scope

The supported synthetic implementation is verified. The full canonical SO-101/Isaac architecture is **not complete**, because the user has explicitly deferred further Isaac worker integration. Deferral is a scope decision, not an implementation claim.

Reviewed baseline: `ae8e6a649bee5ad68b5a264cb1fc82dc9f606ebc`, plus the semantic discovery fix delivered with this audit. The original architecture is unchanged. The prior cloud delivery and full runtime recovery archive are preserved. The later cloud thread could not be retrieved, and GitHub contains no newer agent branch; this report makes no claim about inaccessible work.

Verification: `python -m unittest discover -s tests -q` ran **136 tests in 107.125 seconds: 135 passed, one live PostgreSQL test skipped**. This includes the two-iteration adaptive loop, interruption/reopen recovery, repeated-run idempotency, fixed seven-partition evaluation, training exclusion, terminal recording, catalogue integrity and policy checkpoint tests. The semantic proposal discovery regression passed separately as well.

`python tools/audit_architecture.py` checks exactly 53 canonical headings, all implementation file references and all referenced test identifiers. It validates traceability, not behavioral completeness by file presence. Actual behavioral evidence comes from the regression suite and source review.

## Decision and scope

Proceed with research and development using the supported synthetic factory. Do not describe it as the fully deployed SO-101/Isaac platform. No additional non-Isaac software gap was identified in the reviewed supported contracts after fixing semantic proposal discovery. This is a bounded implementation assessment, not proof of arbitrary task expressiveness, broad robotic competence, throughput or real-world learning.

## Deferred delivery required for full architecture completion

- Governed assignment-to-Isaac execution adapter, compiler configuration realization and physical skill/control plans.
- Runtime/robot/asset/controller/version-scoped measured feasibility approval, including IK, collision, dynamics and physical reference execution. Synthetic approval must not authorize a physical context.
- Calibrated robot/assets/layouts, measured goal/constraint/contact/collision telemetry and synchronized physical terminal trajectory recording.
- Actual SO-101/Isaac closed-loop train/evaluate/adapt execution and GPU validation.

Live PostgreSQL, S3, hosted proposal transport, USD dynamics and hardware remain external validation requirements. Offline tests establish software behavior against fixtures, not service compatibility or hardware evidence. Arbitrary parallel skill graphs and distributed training are not claimed. The architecture allows independent workers and later scale-out, so no cluster deployment is certified here.

The preserved demonstration has 90 durable completions and 14 frozen evaluation cases. Scores stayed 8/14 across the recorded iterations; no learning improvement is claimed. See `architecture-closure-review.md` for model limitations and `recovery/architecture-closures/README.md` for recovery identities.

The semantic discovery fix lowers validated `semantic-1.0` proposals through the compiler's pinned registry before capability,parameter,novelty and publication checks. The source semantic task remains preserved in the lowered representation. Provider vocabulary now advertises all supported schemas. No hosted calls were made.
